# MASTER DEVELOPMENT PROMPT — MHA: RISING HEROES

Build an ambitious, polished **My Hero Academia mod for Minecraft Java Edition 1.21.1 using NeoForge**. Working title: **MHA: Rising Heroes**.

Treat this as a complete game-development project covering programming, combat, progression, world content, animation, VFX, models, interface design, audio, documentation, and testing.

The goal is an exceptional MHA experience with expressive quirks, satisfying progression, spectacular readable combat, a compact professional HUD, and dependable multiplayer.

Include:

- A playable MHA map with **U.A. High and the important series and movie locations**.
- A required **school-to-hero-licence campaign**.
- Substantial **villain and independent/vigilante campaigns**.
- Main-series, movie, and clearly labelled original/non-canon quirks.
- A complete in-game guidebook explaining every implemented quirk, its users, its source, and its gameplay.

Translate the ambition into measurable features and a playable implementation. Work in complete, buildable milestones while preserving the full roadmap.

## 1. Required technology and compatibility proof

Use:

- **Minecraft Java Edition 1.21.1**.
- **NeoForge 21.1.x**.
- **Java 21**.
- **Photon** for attack effects and other quirk VFX.
- **Player Animator** for player animation.
- **Bendy Lib** for supported limb bending.
- A compatible **GeckoLib 4.x** release for animated armour and suitable entities/items.
- **Blockbench, including its browser editor, or Blender** for original models and animations.

Before major implementation, verify exact releases, loader metadata, dependencies, licensing, distribution requirements, and client/server requirements from author-maintained sources. Pin a reproducible working combination.

Include Photon’s required supporting libraries. Do not invent Maven coordinates or copy examples from a different Minecraft or GeckoLib major version.

Investigate Bendy Lib through its author’s artifacts and source, rather than relying solely on an old standalone download listing. Record Player Animator’s maintenance status. Preserve my requested stack; propose a replacement only if a specific blocker is demonstrated, explaining the tradeoff before changing it.

Build an early integration scene containing:

- One server-authoritative attack.
- A Photon effect.
- A Player Animator animation.
- Bendy limb movement.
- A GeckoLib armour set correctly following the player.

Verify standard and slim skins, first and third person, another player observing, walking, sprinting, crouching, jumping, swimming, riding, equipment changes, and interrupted attacks.

Check shoulders, elbows, knees, held items, and attachments. Treat armour pose transfer and bending as an integration task; do not assume the libraries automatically share a rig.

Keep client rendering code out of dedicated-server execution. Produce a dependency matrix and get both client and dedicated server to start before expanding content.

## 2. Overall experience and creative direction

The main loop is:

**Discover a quirk → learn its controls → train through meaningful activities → complete missions → unlock techniques → specialise → earn a licence or equivalent reputation → challenge bosses → master advanced abilities.**

Support single-player survival, LAN, and dedicated servers. Preserve the usefulness of food, crafting, exploration, shelters, equipment, and building. Also provide configuration for adventure and roleplay servers.

Provide **hero, villain, and independent/vigilante paths**. These change missions, relationships, headquarters, and cosmetics. A player’s quirk must not dictate their alignment or lock them out of essential progression. Make changing direction possible through meaningful quests.

Use a cohesive anime-inspired visual identity:

- Strong silhouettes and purposeful poses.
- Clean icons and readable typography.
- Restrained interface decoration.
- Distinct colour languages for different quirks.
- Detailed costumes with consistent proportions.
- Spectacular effects that preserve combat readability.

The HUD should feel deliberately designed, smooth, and compact. Avoid oversized panels, muddy generated textures, fake lettering, and inconsistent icon styles.

Create a style guide covering palettes, typography, icon grids, proportions, materials, VFX intensity, and audio levels.

## 3. Random starting quirk and onboarding

Assign exactly **one enabled, completed quirk** on a player’s first eligible join. The server owns the random selection and persists it before displaying the reveal.

Death, reconnecting, dimension changes, and repeated requests must never produce another free roll.

Use configurable pools and weights. Make every starting result viable. Acquisition rarity must not automatically mean greater combat power.

Allow separate main-series, movie, and original-content pools, plus individual allowlists and exclusions. Story-gated quirks stay outside ordinary rolls unless the server explicitly enables them.

Provide a brief, skippable reveal showing:

- Quirk name.
- Combat/support role.
- Main resource and drawback.
- Beginner controls.
- First suggested training objective.

Give two useful starter techniques and the guidebook. Make the tutorial replayable.

Do not randomly give quirkless starts by default. Provide a deliberate optional quirkless challenge with equipment-based progression.

Persist current quirk, individual quirk masteries, unlocks, loadouts, reputation, mission state, tutorial completion, cosmetics, and pending reroll offers in versioned player data.

Examples:

Possessing a creative token in survival must not bypass progression by default.

Ordinary assignment restores that quirk’s previously earned mastery or starts it at zero. Provide separate, clearly labelled creative testing controls for maximum mastery, all moves, and resource overrides.

Changing a quirk must not silently grant everything or wipe all character progress.

Provide documented permission-controlled commands under `/mha` for:

- Assigning a quirk.
- Granting a reroll.

## 5. Earnable rerolls and targeted acquisition

Create a survival **Quirk Reroll Token** distinct from creative assignment tokens.

Award one bound introductory token after the tutorial. Provide further routes through mission credits, research tasks, bosses, and a balanced crafting or exchange recipe.

Target roughly **45–90 minutes of purposeful early play** for another reroll, then adjust through testing.

Before spending it, explain exactly what changes and what is retained.

On confirmation:

1. Consume one token.
2. Generate up to three distinct eligible alternatives.
3. Exclude the current quirk when the pool permits.
4. Save the offers immediately.
5. Let the player select an alternative or keep their current quirk.

Reopening the menu or reconnecting must show the same choices. Offer fewer choices for small pools. If no eligible alternative exists, explain why and do not consume a token.

Explicitly state that generating offers spends the token even if the player keeps their current quirk.

Prevent duplicate consumption, free refreshes, and reward duplication. Disable rerolls during combat, duels, transformations, and missions requiring stable loadouts.

Retain general rank, story progress, currency, recipes, cosmetics, and archived mastery for previously trained quirks. A new quirk begins at its own earned mastery. Archived powers do not remain active.

Preserve relevant cooldown and exhaustion restrictions so switching cannot refresh combat resources unfairly.

Add a longer deterministic research or attunement route toward an eligible desired quirk. Players should not be trapped behind endless random rolls.

Avoid paid rolls, login streaks, mandatory daily tasks, and real-time waiting gates.

## 6. Progression and move unlocks

Separate three understandable tracks:

| Track | Purpose |
|---|---|
| Character rank, approximately 1–50 | Opens missions, licences, equipment, and facilities. |
| Quirk mastery, 0–100 per quirk | Unlocks control, techniques, branches, and advanced forms. |
| Technique proficiency | Provides a few modest refinements or alternative behaviours. |

Progression should mainly add options, control, and build variety. Keep health, damage, and defence growth bounded so newer players can contribute.

Suggested mastery milestones:

| Mastery | Reward |
|---|---|
| 0 | Starter kit and resource tutorial. |
| 5 | First additional technique. |
| 12 | Utility or efficiency improvement. |
| 20 | Signature move and first specialisation. |
| 35 | Advanced defence or movement. |
| 50 | Ultimate trial. |
| 65 | Technique variant. |
| 80 | Advanced combinations. |
| 100 | Capstone trial. |

Treat these as tunable defaults.

Unlock moves through a visible mastery requirement plus a short, relevant challenge. Examples include:

- Rescuing civilians without fall damage.
- Controlling temperature.
- Completing an Explosion movement course.
- Protecting allies.
- Maintaining and breaking line of sight correctly.

Permit equivalent routes when a particular structure or mentor is unavailable in an existing world.

Reward effective combat, legitimate healing, protection, rescue work, traversal objectives, and mission contributions.

Prevent AFK casting, friendly damage, self-damage, and repeated trivial targets from generating unlimited mastery. Training dummies should teach mechanics and provide limited introductory progress.

Aim for a useful unlock in the first **10–20 minutes** and a recognisable build within the first hour. Verify pacing through actual play.

Use two or three meaningful specialisation branches per major quirk, with tradeoffs in range, mobility, recovery, cost, or utility. Allow an accessible respec.

Do not force a lore-inaccurate awakening onto every quirk. A perfected technique, advanced stance, or support capstone can fill that role.

## 10. Combat, controls, and resource rules

Use responsive aiming, useful melee, dodging, guarding, aerial combat, and quirk-specific mobility.

Ordinary weapons and unarmed combat should remain usable. Provide readable hit confirmation and optional light camera feedback.

The default loadout has **six slots**:

- Four techniques.
- One mobility/utility move.
- One ultimate/capstone.

Allow safe-area loadout changes and saved presets. Keep cooldowns attached to abilities so swapping cannot bypass them.

Make all keys remappable. Offer direct move bindings and a select-and-cast option.

Define press, hold, release, charging, toggles, cancellation, and buffered inputs consistently. Display actual configured keys.

Preserve normal inventory, hotbar, sneak, sprint, and chat controls. Detect conflicts.

Use explicit startup, active, and recovery states. Define interruption and cancellation costs.

Stamina controls exertion; individual quirk resources distinguish kits. Zero stamina should prevent demanding actions without making basic survival impossible.

Integrate hunger sensibly so ordinary combat does not require eating every few seconds.

Use bounded crowd control, repeated-suppression resistance, limited knockback chains, and escape opportunities.

Strong attacks require setup, a tell, a cost, and recovery. Provide configurable PvP, friendly fire, duels, and protected hubs.

**The server owns damage, costs, cooldowns, movement validation, targets, and rewards.** Photon and animation completion must never decide authoritative hits.

## 11. Special rules for difficult powers

- **All For One:** bounded NPC-derived imprints, capped storage/equipped powers, and a shared resource budget. No permanent theft of another player’s quirk by default.
- **Copy:** temporary eligible abilities, with restrictions for stockpiled power, recursive copying, and incompatible transformations.
- **Decay:** telegraphed, finite propagation with block/entity budgets and ordinary resistible damage.
- **Overhaul/Alchemy:** curated temporary formations and bounded reconstruction. Never duplicate inventories, containers, valuable blocks, or entity drops.
- **Permeation/Voidstep:** bounded duration and distance, no attacking or looting while intangible, protected-area checks, safe destination validation, and fallback positions.
- **Creation:** explicit recipes, allowlists, real costs, and caps. No administrative items, reroll tokens, progression keys, or arbitrary item generation.
- **Double/Mummification/summons:** strict entity limits, simplified AI, finite lifetimes, and no recursive armies or duplicated inventories.
- **Transform:** disguise appearance without copying identity, permissions, or team membership.
- **Warp Gate:** permission-aware destinations, bounded range, and safe arrival validation.
- **Rewind:** carefully scoped reversible effects with explicit exclusions. No arbitrary world-history rollback or permanent deletion of another player’s progress.
- **Reflect:** capped categories, capacity, duration, and reflection depth.
- **Hologram/Soul/Brainwashing:** state what is simulated and what is an adaptation. Illusions must not become unrestricted wall vision; control effects must remain brief and escapable.

Test these interactions deliberately. Low-detail settings must not remove essential danger information.

## 17. Required school campaign and hero licences

In the default hero campaign, players **must attend U.A. and complete school missions and examinations to earn their hero licence**.

Make requirements visible in the notebook, map, and quest journal.

Build this connected, game-adapted progression chain:

1. **Application and entrance assessment:** demonstrate basic control, combat, and rescue potential; meet staff and enrol.
2. **Orientation:** receive a student record, dorm access, beginner costume/support options, and a training plan.
3. **Fundamental lessons:** control, stamina, movement, targeting, defence, first aid, and judgement around civilians.
4. **Battle trials and team exercises:** complete objectives with classmates or competent NPC allies.
5. **USJ rescue training:** handle flood, fire, rubble, and evacuation scenarios through different valid approaches.
6. **Sports Festival and assessments:** participate in movement, team, and combat events; first place and PvP victories must not be mandatory.
7. **Supervised internships and field assignments:** work with an agency and complete city missions.
8. **Provisional hero licence examination:** pass checkpointed rescue, combat, teamwork, and judgement tasks.
9. **Licensed work studies and patrols:** unlock sanctioned fieldwork, advanced contracts, and appropriate equipment.
10. **Advanced qualification and graduation:** complete further training and a major operation to earn the mod’s professional-hero status, then develop or join an agency.

Identify invented qualification requirements and mission sequencing as the mod’s adaptation. Verify canonical terminology.

Use memorable missions, conversations, objective changes, and rewards. Do not reduce every lesson to killing mobs or clicking through dialogue.

Grade control, rescue, efficiency, teamwork, and collateral damage. Support defensive, mobility, support, and equipment-based builds.

No rare quirk, mandatory PvP win, paid item, or real-time attendance schedule may be required.

Keep lessons playable, with practice options, checkpoints, feedback, and reasonable retries.

Licences should unlock meaningful opportunities: student activities, provisional patrols, agency work, specialised vendors, advanced missions, and professional operations.

Store enrolment, completed lessons, examination results, and licence level on the server.

Include scouting, retrieving contested information, intercepting guarded shipments, extracting NPC allies, infiltrating agencies, defending hideouts, and confronting rival factions.

Respect server protection rules. Progress must not require harassing real players or destroying their homes.

Track faction trust, notoriety, and operational rank separately from quirk mastery.

Unlock contacts, workshops, equipment, safehouses, specialised missions, and crew leadership.

Use pursuit and capture mechanics with bounded consequences and a clear recovery route.

Give independent/vigilante players investigation, rescue, bounty, exploration, and support contracts with equivalent access to essential resources.

Allow allegiance changes through rehabilitation, recruitment, or breakaway missions while retaining earned mastery. Preview effects on reputation, access, and credentials.

Build reusable mission definitions containing:

- ID and prerequisites.
- Location and NPC contact.
- Objective stages.
- Contribution rules.
- Failure and retry conditions.
- Rewards and rank changes.
- Spoiler and source tags.

Persist checkpoints, branch decisions, and unique reward claims.

Death, reconnects, rerolls, and party changes must not duplicate rewards or erase completed school progress. Track group participation individually.

Support solo players and parties. Keep private mission progress separate from global world state.

Use reserved arenas or a proven encounter-session system when story stages conflict. Never reset player builds to replay an exam or boss.

Provide support-item research, crafting benches, vendors, mentors, civilians, criminals, robots, and advanced enemies with purposeful, bounded AI.

Bosses need telegraphed attacks, phases, positioning challenges, interrupt opportunities, and distinct rewards.

Endgame should include mastery trials, advanced missions, cooperative raids, optional arenas, agency/crew progression, build experimentation, collections, and cosmetics.

Verify complete hero-school-to-licence and villain progression playthroughs before claiming campaign completion.

## 19. Multiplayer, persistence, and performance

Validate each cast’s quirk, unlock, slot, resource, cooldown, state, range, target, and permission on the server.

Clients must not award themselves damage, movement, items, or experience.

Use unique cast/reward identities and rate limits to prevent duplicate actions and packet spam.

Synchronise necessary state and effect events to relevant observers. Handle late tracking, reconnects, and cancellations. Use prediction only with authoritative reconciliation.

Make assignment, rerolls, purchases, and rewards transactional and repeat-safe.

Version save formats and provide migrations. Clean up transient entities, effects, and modifiers while preserving durable progress.

Respect PvP policy, protected regions, and terrain rules.

Default destructive attacks to restrained environmental effects, with configurable real destruction.

Bound blast radius, propagation, temporary-block counts, and cleanup work. Never overwrite later building changes during restoration or duplicate containers and drops.

Do not force-load large regions for abilities.

Bound projectile lifetimes, summons, collision queries, and AI work. Test travel near chunk boundaries, borders, liquids, and restricted areas.

Establish a benchmark such as eight nearby active quirk users plus NPCs and sustained effects.

Record hardware, settings, server tick times, client frame times, and memory behaviour. Measure before claiming performance.

## 22. Acceptance criteria and deliverables

Verify that:

- Initial assignment happens exactly once.
- Creative tokens respect permissions.
- Locked moves reject spoofed requests.
- Earned unlocks work.
- Rerolls retain offers and consume one legitimate cost.
- Old powers cannot survive reassignment.
- Archived mastery restores correctly.
- Support players progress meaningfully.
- Death, reconnects, and dimension changes preserve intended data.
- Attacks have matching hitboxes and readable tells.
- Armour follows animation.
- Remote players see correct effects.
- Interruptions clean up poses and loops.
- Low-detail modes remain fair.
- HUD layouts work across supported scales.
- Guidebook values match server values.
- Source information and spoiler settings work.
- Advertised locations are reachable and populated.
- Maps show correct objectives.
- A copied licence item cannot bypass school progression.
- Hero and villain campaigns work solo and in multiplayer.
- Dedicated servers load safely.

Test dangerous boundaries including recursive reflection, summons, item creation, phasing, destruction, copying, reward duplication, and save migration.

Use focused automated tests for meaningful logic, supplemented by in-game visual and multiplayer checks.

Deliver:

- Complete source project and Gradle wrapper.
- Pinned dependencies.
- Built mod JAR when successfully compiled.
- Editable model, animation, interface, and VFX sources.

- Configuration reference.
- Guidebook and region atlas.
- Mission/licence progression documentation.
- Content/source matrix.
- Changelog, known limitations, and test results.

Use actual tools to implement and verify. Do not present pseudocode, empty classes, placeholder icons, or a plan as a finished mod.

If blocked, identify the concrete blocker and continue independent work. Never fabricate test results, compatibility claims, or lore.
